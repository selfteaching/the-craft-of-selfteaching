# گزارش بازبینی و وضعیت ترجمهٔ بخش دوم

## اثر اصلی و اجازهٔ استفاده

نویسندهٔ اثر اصلی **لی شیائولای — Li Xiaolai (李笑来)** است. این ترجمه بر پایهٔ نسخهٔ Markdown کتاب **The Craft of Self-Teaching (自学是门手艺)** در [مخزن اصلی selfteaching/the-craft-of-selfteaching](https://github.com/selfteaching/the-craft-of-selfteaching) تهیه شده است. [متن اصلی فصل پایانی بخش دوم، به زبان چینی](../../markdown/Part.2.E.deliberate-thinking.md) نیز در همین نسخهٔ محلی موجود است.

مجوز اعلام‌شدهٔ اثر اصلی **[CC BY-NC-ND 3.0](https://creativecommons.org/licenses/by-nc-nd/3.0/)** است. نام نویسنده، انتساب منابع و اطلاعات مجوز اصلی حفظ می‌شود. این ترجمه فقط برای **مطالعهٔ شخصی و به‌صورت محلی** تهیه شده است؛ اجازهٔ انتشار ترجمه دریافت نشده و مجوز اعلام‌شده نباید به‌عنوان اجازهٔ انتشار ترجمه تلقی شود. تا دریافت اجازهٔ لازم از صاحب حق، انتشار یا ارسال به مخزن، فورک یا branch عمومی مجاز شمرده نمی‌شود. بی‌پاسخ ماندن درخواست اجازه نیز به معنی موافقت نیست. در این مرحله هیچ انتشار، push، deploy یا بارگذاری عمومی انجام نشده است.

## وضعیت فصل‌ها

**هر ۱۲ فصل بخش دوم، شامل A، B، C، D.1 تا D.8 و E، ترجمه و بازبینی‌شده‌اند؛ هیچ‌یک «نهایی» اعلام نمی‌شود.** پیوند هر ۱۲ فصل به‌ترتیب در [فهرست فارسی، قسمت بخش دوم](TOC.md) آمده است.

- فصل E به‌طور کامل از متن چینی ترجمه و سپس از نظر معنا و پوشش مطالب با همان متن مقابله شد؛ مثال‌ها، استدلال‌ها و انتساب‌های نویسنده حفظ شدند. توضیح‌های افزوده با برچسب یادداشت مترجم از متن اصلی جدا شده‌اند.
- یازده فصل قبلی در این مرحله بازنویسی نشدند. بازبینی این مرحله برای آن‌ها شامل تطبیق بلوک‌های کد و خروجی با اصل، کنترل وجود فصل‌ها و مقصدهای محلی پیوندها و تصاویر بود؛ ادعای مقابلهٔ معنایی دوبارهٔ تک‌تک جمله‌های آن یازده فصل نیست.
- ابهام‌های متن اصلی، خطاهای احتمالی و محدودیت‌های تاریخی یا فنی در یادداشت‌های مترجمِ فصل مربوط مشخص شده‌اند و با اصلاح بی‌صدای متن نویسنده پنهان نشده‌اند. از جمله، در فصل E ترتیب نام «Clegg Dai» و مشخصات انتساب MoSCoW Method نیازمند بررسی کتاب‌شناختی مانده است.

## بررسی‌های انجام‌شده و محدودیت‌ها

- وجود هر ۱۲ فایل ترجمه و پیوند آن‌ها در فهرست کنترل شد. مقصدهای محلی پیوندها و تصاویر در فصل‌های بخش دوم، فهرست و همین گزارش از نظر وجود فایل بررسی شدند. در این مجموعه پیوند محلیِ دارای fragment وجود نداشت؛ بنابراین صحت anchor در رندر واقعی آزموده نشده است.
- بلوک‌های fenced کد و خروجی و بلوک‌های خروجیِ تورفتهٔ هر ۱۲ فصل با اصل مقایسه شدند و یکسان بودند. **کدها و خروجی‌های ثبت‌شده تغییر نکرده‌اند و مثال‌ها اجرا نشده‌اند.** فصل E بلوک کد یا خروجی اجرایی ندارد. یکسان بودن با اصل، تأیید صحت فنی یا سازگاری با نسخه‌های امروز نیست.
- **پیوندهای خارجی به‌صورت زنده آزموده نشده‌اند.** وجود یک پیوند در متن به معنی تأیید دسترس‌پذیری کنونی آن نیست.
- **نمایش راست‌به‌چپ و ترکیب فارسی با متن چپ‌به‌راست، جدول‌ها و تصاویر به‌صورت بصری رندر و بررسی نشده است.** بررسی متنی و مسیرهای محلی جای آزمون مرورگر یا GitHub را نمی‌گیرد.
- محدودهٔ تغییرات این مرحله فقط ترجمهٔ E، افزودن بخش دوم به فهرست فارسی و ایجاد همین گزارش است. متن قبلی فهرست حفظ شده است؛ فایل‌های اصلی، Notebookها، دیگر ترجمه‌ها و تغییرات قبلی کاربر خارج از این محدوده دست‌نخورده مانده‌اند.

## واژه‌نامهٔ کوتاه مشترک

نام‌های فنی انگلیسی حفظ می‌شوند؛ توضیح‌های زیر فقط مفهوم آن‌ها را روشن می‌کند، نه اینکه جایگزین نامشان شود.

| اصطلاح | توضیح سادهٔ مفهوم |
| --- | --- |
| function | مجموعه‌ای از دستورها که با فراخوانی آن، کار مشخصی انجام می‌شود. |
| parameter / argument | parameter نامی در تعریف function برای دریافت مقدار است؛ argument مقداری است که هنگام فراخوانی به آن داده می‌شود. |
| lambda | شکلی کوتاه برای ساختن function بی‌نام با یک عبارت. |
| recursion | روشی که در آن function مستقیم یا غیرمستقیم خودش را فراخوانی می‌کند و برای پایان یافتن به شرط توقف نیاز دارد. |
| Docstring | متنی در ابتدای تعریف function، class یا module که برای مستندسازی آن به کار می‌رود. |
| module / import | module واحدی برای سازمان‌دهی کد است؛ import راه دسترسی به آن در کد دیگر است. |
| Test Driven Development (TDD) | روشی که در آن ابتدا آزمونِ رفتار مورد انتظار نوشته می‌شود، سپس کد لازم برای گذراندن آن و بهبود ساختار کد دنبال می‌شود. |
| string / method | string دادهٔ متنی است؛ method عملیاتی است که از طریق یک object، مانند یک string، در دسترس قرار می‌گیرد. |
| MoSCoW Method | شیوه‌ای برای اولویت‌بندی نیازها با چهار برچسب Must have، Should have، Could have و Won't have. |
